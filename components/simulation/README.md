# Thermal Simulation Component (C++20)

Thermal physics simulator for the **BGA Reflow Controller**, running natively on **ESP-IDF v6.0.2** and **FreeRTOS**.

This component simulates dual-zone thermal mass physics (Top infrared heater and Bottom preheater plate), ambient heat dissipation, and forced-air cooling, enabling full dry-run testing of reflow profiles, PID tuning, and the Web UI without connecting high-voltage 230V hardware.

---

## 1. Overview & System Integration

When developing, tuning, or demonstrating the BGA Reflow Controller, operating high-power heating elements (up to 2000W) poses safety hazards and consumes electrical power. 

The `simulation` component provides an internal thermodynamic physics model that completely replaces physical MAX31856 thermocouple hardware when **Simulation Mode** (`simulationMode = true`) is active in `MachineSettings`:

```
                           +----------------------------------------+
                           |       control_task (Core 1, 5 Hz)      |
                           +----------------------------------------+
                                         |            |
                  [ Live Mode: false ]   |            |   [ Simulation Mode: true ]
                                         v            v
                    +----------------------+        +------------------------------+
                    |  sensor::MAX31856    |        |   sim::ThermalSimulator      |
                    |  (Live SPI Hardware) |        |   (Thermodynamic Model)      |
                    +----------------------+        +------------------------------+
                                         \            /
                                          \          / (Simulated Temps)
                                           v        v
                                    +-----------------------+
                                    | AppController Mailbox |
                                    | (publishSensorSnapshot)
                                    +-----------------------+
                                                |
                               +----------------+----------------+
                               |                                 |
                               v                                 v
                    +---------------------+           +---------------------+
                    |   Dual PID Loops    |           |   Reflow FSM & UI   |
                    |   (Top & Bottom)    |           |   (Web live chart)  |
                    +---------------------+           +---------------------+
                               |
                               v (Power 0..100%)
                    +-------------------------------------+
                    |       output::OutputManager         |
                    | [SIMULATION MODE: SSRs FORCED OFF!] |
                    +-------------------------------------+
```

## 2. Thermodynamic Physics Model

[`ThermalSimulator`](include/simulation/thermal_simulator.hpp) uses discrete Euler-forward numerical integration to model heat transfer per zone over discrete time intervals $\Delta t = 200\,\text{ms}$ (`config::Timing::CONTROL_LOOP_PERIOD_MS`).

### A. General Differential Equation
$$\frac{dT}{dt} = \dot{Q}_{\text{in}} - \dot{Q}_{\text{ambient}} - \dot{Q}_{\text{fan}}$$

Where:
* $\dot{Q}_{\text{in}}$: Heat flux generated by electrical power ($P \in [0.0, 100.0]\%$).
* $\dot{Q}_{\text{ambient}}$: Natural convective and radiative heat loss to room temperature ($T_{\text{ambient}} = 25.0^\circ\text{C}$).
* $\dot{Q}_{\text{fan}}$: Forced convection cooling rate when the cooling fan is running.

---

### B. Thermal Profiles: Top vs. Bottom Heaters

The simulation mirrors the distinct physical characteristics of the two heating elements:

| Physical Property | Top Infrared Heater (`_topTemp`) | Bottom Preheater Plate (`_bottomTemp`) |
| :--- | :---: | :---: |
| **Heater Construction** | Fast quartz / ceramic dark-emitter | Heavy ceramic / aluminum bed plate |
| **Thermal Mass / Inertia** | Low thermal mass (agile ramp) | High thermal mass (slow response) |
| **Max Ramp Rate (100% Power)** | **~3.5 °C/s** (`P * 0.035`) | **~1.5 °C/s** (`P * 0.015`) |
| **Natural Heat Dissipation** | $0.005 \times (T - T_{\text{ambient}})$ | $0.002 \times (T - T_{\text{ambient}})$ |
| **Fan Cooling Coefficient** | $0.020 \times (T - T_{\text{ambient}})$ | $0.005 \times (T - T_{\text{ambient}})$ |
| **Lower Clamping Floor** | $T_{\text{ambient}} = 25.0^\circ\text{C}$ | $T_{\text{ambient}} = 25.0^\circ\text{C}$ |

---

### C. Discrete Integration Step

In every 200 ms control loop cycle ($\Delta t = 0.2\,\text{s}$):

$$\Delta T_{\text{top}} = \left(0.035 \cdot P_{\text{top}} - 0.005 \cdot (T_{\text{top}} - 25) - 0.020 \cdot \text{fan} \cdot (T_{\text{top}} - 25)\right) \cdot \Delta t$$

$$\Delta T_{\text{bot}} = \left(0.015 \cdot P_{\text{bot}} - 0.002 \cdot (T_{\text{bot}} - 25) - 0.005 \cdot \text{fan} \cdot (T_{\text{bot}} - 25)\right) \cdot \Delta t$$

$$T(t + \Delta t) = \max\left(T(t) + \Delta T,\, 25.0^\circ\text{C}\right)$$

## 3. Bench Safety Lockout in Simulation Mode

To guarantee that dry runs never inadvertently heat physical elements:
* When `MachineSettings::simulationMode` is `true`, `AppController` automatically calls `outputs.setSimulationMode(true)`.
* In `OutputManager`, physical SSR GPIO pins (GPIO 4 & 5) are **hard-locked to the electrical OFF state** at the driver level.
* Real SSRs remain completely de-energized, while all virtual temperatures, PID outputs, FSM transitions, and live chart streams run with full fidelity.

## 4. Usage Example (ESP-IDF C++)

```cpp
#include "simulation/thermal_simulator.hpp"
#include "esp_log.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

static const char* TAG = "SimExample";

sim::ThermalSimulator simulator;

void app_main() {
    // 1. Reset simulator to room temperature (25°C)
    simulator.reset(sim::ThermalSimulator::AMBIENT_TEMP);

    // 2. Simulate 10 seconds of 80% Top power and 50% Bottom power without fan
    const uint32_t dtMs = 200; // 5 Hz cycle
    const int totalTicks = (10 * 1000) / dtMs;

    for (int i = 0; i < totalTicks; ++i) {
        float topPower = 80.0f;
        float botPower = 50.0f;
        bool fanActive = false;

        // Step simulation physics by dtMs
        simulator.update(topPower, botPower, fanActive, dtMs);

        ESP_LOGI(TAG, "Tick %d: Top=%.1f°C | Bot=%.1f°C",
                 i, simulator.getTopTemperature(), simulator.getBottomTemperature());

        vTaskDelay(pdMS_TO_TICKS(dtMs));
    }
}
```

## 5. API Reference

### `sim::ThermalSimulator`

| Method / Constant | Description |
| :--- | :--- |
| `static constexpr float AMBIENT_TEMP` | Constant defining room temperature baseline (`25.0f` °C). |
| `ThermalSimulator()` | Default constructor (initializes both zones to 25.0 °C). |
| `void reset(float initialTemp)` | Resets Top and Bottom temperatures to a defined starting value (default: `25.0f` °C). |
| `void update(float topPower, float bottomPower, bool fanActive, uint32_t dtMs)` | Steps thermal physics forward by `dtMs` milliseconds based on current power and fan state. |
| `float getTopTemperature() const` | Returns current simulated Top Heater temperature in °C. |
| `float getBottomTemperature() const` | Returns current simulated Bottom Preheater temperature in °C. |
| `void setTopTemperature(float temp)` | Overrides current Top temperature (useful for testbench presets). |
| `void setBottomTemperature(float temp)` | Overrides current Bottom temperature. |

## 6. Unit Tests & Automated Verification

The component includes 100 % automated test coverage in [`test/test_simulation.cpp`](test/test_simulation.cpp):

1. **`test_sim_initial_conditions`**: Verifies reset to `AMBIENT_TEMP` (25 °C) and arbitrary custom starting temperatures.
2. **`test_sim_top_heating_ramp`**: Verifies that 100 % Top power increases Top temperature to expected range (> 40 °C after 5s) while Bottom temperature remains isolated at ambient.
3. **`test_sim_bottom_heating_ramp`**: Verifies slower heating curve of Bottom ceramic preheater (> 37 °C after 10s) while Top temperature remains isolated.
4. **`test_sim_fan_cooling`**: Compares passive ambient loss against active forced convection fan cooling, ensuring fan accelerates temperature decay.
5. **`test_sim_clamping`**: Verifies that temperature never drops below `AMBIENT_TEMP` (25.0 °C), even with prolonged fan cooling.
6. **`test_sim_simultaneous_heating_and_cooling`**: Verifies realistic net heat flux when heaters and fan run concurrently.
7. **`test_sim_nan_inf_power_protection`**: Verifies that NaN and Inf power inputs are rejected, preventing state corruption.
8. **`test_sim_power_clamping`**: Confirms power inputs are clamped to `[0.0, 100.0] %`, preventing unphysical sub-ambient chilling.
9. **`test_sim_nan_inf_override_protection`**: Confirms that `reset()` and direct `set...Temperature()` calls reject NaN and Inf overrides, self-healing to `AMBIENT_TEMP`.
